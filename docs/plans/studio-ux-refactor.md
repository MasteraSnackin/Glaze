# Studio UX: разбор текущего состояния и план разгребания

Статус: **анализ + предложение**, ничего из плана ещё не реализовано.

Документ описывает, как интерфейс Studio устроен сейчас, почему пользователи называют
его непонятным и перегруженным, и в каком порядке это чинить. Концептуальная модель
самой фичи (фазы, режимы, память) — в `docs/STUDIO_OVERVIEW.md`; здесь только UI и
модель данных под ним.

---

## 1. Карта текущего UX

### Точки входа

| Где | Что открывается | Код |
|---|---|---|
| Настройки → Экспериментальные функции | мастер-тумблер «Студия» | `lib/features/extensions/screens/extensions_screen.dart:44` |
| Tools → плитка Studio | `StudioSettingsSheet` без сессии | `lib/features/tools/tools_screen.dart:129` |
| Чат → Quick Access → Studio | `StudioSettingsSheet` с сессией | `lib/features/chat/widgets/magic_drawer.dart:564` |
| Чат → Quick Access → Agentic Ops | лог операций, 4 таба | `lib/features/chat/widgets/agentic_operations_log_dialog.dart` |
| Чат во время генерации | `StudioStatusCard`, прогресс n/4 | `lib/features/chat/chat_screen.dart:1704` |
| Меню сообщения | «Re-run cleaner», только при включённой Studio | `lib/features/chat/chat_screen.dart:1298` |

### Иерархия внутри хаба

```
StudioSettingsSheet
├── Studio Enabled                    → StudioConfig.enabled   (сессия / профиль)
├── Studio Mode          ▾            → executionMode активного пресета
├── Studio Preset        ▾            → Create / Import / список (export, delete)
├── Models: Final | Trackers | Cleaner
│   ├── дропдаун модели               → PipelineSettings (глобально)
│   ├── «Другой API» + выбор конфига  → StudioConfig.*ApiConfigId
│   └── ⚙ tune → StudioSlotSettingsDialog (temp, topP/topK, penalties,
│                reasoning, maxTokens, timeout, extra params)
├── Post-Gen: «Пост-клинер»           → PipelineSettings.cleaner
├── Agents           →  StudioAgentsSheet  (preset.agentEnabled)
├── Edit Preset Blocks → StudioPresetEditorSheet
│         └── чипы секций (Trackers / Final Agent / Post-Processing /
│             Canon Ledger / Build / Brief Parser)
│             └── блок → StudioBlockEditorDialog
├── Post-Processing: 1 / 2 / 3 / 5 сообщений трекерам
└── Recovery                          — только при входе из чата
```

Редактор блоков доступен только по пути **Studio → Edit Preset Blocks**
(`lib/features/chat/widgets/studio_settings_sheet.dart:255`) и всегда открывает
**активный** пресет — отредактировать неактивный нельзя, сначала надо на него
переключиться.

## 2. Диагноз: четыре слоя описывают одно и то же

«Какие агенты запустятся на следующем ходу» определяется четырьмя независимыми
сущностями в четырёх разных местах UI и в четырёх разных хранилищах:

| Слой | Где настраивается | Где хранится |
|---|---|---|
| Мастер-тумблер Studio | Настройки → Экспериментальные | SharedPreferences |
| `StudioConfig.enabled` | шит Studio, первый свитч | БД, на сессию/профиль |
| `executionMode` (режим) | шит Studio, «Studio Mode» | **поле пресета** |
| `agentEnabled` + `block.enabled` | шит Agents + редактор блоков | внутри пресета |

Пользователь воспринимает это как одну настройку с разной степенью детализации.
На деле верхний слой молча перекрывает нижние — отсюда ощущение «потыкал, ничего
не изменилось».

К этому добавляется пятое хранилище: модели и сэмплеры слотов лежат в
`PipelineSettings` (глобально), а API-конфиги слотов — в `StudioConfig`
(сессия/профиль). Итого в одном скролле смешаны пять источников без единой подписи.

## 3. Три главные боли

### 3.1 Режимы

Режим — жёсткий гейт, а не подсказка (`lib/core/llm/studio_activation_gate.dart:21`):

```dart
StudioExecutionMode.direct   => specId == 'final',
StudioExecutionMode.assisted => final | continuity | narrative | beauty,
StudioExecutionMode.legacy   => true,
```

`applyExecutionMode` (`:36`) принудительно гасит любой pregen-агент, не разрешённый
режимом — специально, чтобы пережить смену пресета, у которого persisted-агенты
могли остаться от прошлой конфигурации.

При этом `executionMode` — **поле пресета**, а не настройка. Поэтому селектор
«Studio Mode» не переключает режим, а **ищет другой пресет** с нужным режимом,
с приоритетом по имени, начинающемуся на `Loom Adapt v1`
(`lib/features/chat/widgets/studio_settings_sheet.dart:367`). Не нашёл — тост
«Import a … Studio preset first», и режим молча остаётся прежним.

Что видит пользователь: выбрал «Direct Loom» → поменялся весь набор блоков и
агентов (потому что подменился пресет). Или не поменялось ничего, и непонятно почему.

**Ключевое наблюдение:** режим — не отдельная сущность, а сокращение для «сколько
контроллеров включено». Direct = только автор, Assisted = двое-трое + автор,
Legacy = все. Хранение режима отдельно от `agentEnabled` гарантирует рассинхрон,
который и приходится лечить принудительным гашением.

### 3.2 Агенты

Три источника правды на один тумблер:

1. **Agents sheet** пишет в `preset.agentEnabled` — но не для всех: `beauty`
   читается и пишется через три блока `beauty_extractor / beauty_task /
   cleaner_beauty` (`lib/features/chat/widgets/studio_agents_sheet.dart:10`, `:119`).
   Один тумблер = три сущности, видно только в коде.
2. **Редактор блоков** правит `block.enabled` по секциям — те же агенты, но с
   другой стороны и под другими именами.
3. **Режим** перекрывает оба.

Главный ляп: тумблер, запрещённый режимом, рендерится как `onChanged: null`
(`studio_agents_sheet.dart:145`), но значение показывает старое. Continuity в
Direct-режиме выглядит как «включён, но серый», без объяснения. Пользователь видит
включённый агент, который не работает.

Плюс `enabledMap[spec.id] ?? true` (`:125`) — «по умолчанию всё включено», но нигде
не написано.

Отдельно: **модели настраиваются не по агентам, а по трём слотам** (Final /
Trackers / Cleaner). Все 8 pregen-контроллеров делят один слот Trackers — задать
Continuity одну модель, а Scene Director другую нельзя в принципе. Связь
«агент → слот» в UI не показана.

### 3.3 Пресеты

«Studio Preset» звучит как «пресет сэмплеров» — что-то лёгкое и переключаемое.
На деле это вся конфигурация пайплайна: блоки промптов, `agentEnabled`, режим.
Переключение пресета = смена всего поведения Studio.

В селекторе есть Create / Import / Export / Delete и **нет «Редактировать»**.
Создание описано как «скопировать текущий набор блоков» без объяснения, что именно
копируется.

## 4. Остальные проблемы

- **Мастер-тумблер невидим из шита.** `studioFeatureEnabledProvider` перекрывает всё
  (`lib/core/state/db_provider.dart:161`), но в шите про него ни слова: можно щёлкать
  «Studio Enabled» и не понимать, почему ничего не запускается.
- **Scope нигде не подписан.** Что глобальное, что на этот чат — определить нельзя.
  Из Tools ещё и Recovery исчезает без объяснения.
- **Локализация.** Плитка в Tools локализована, внутри всё захардкожено: английский
  вперемешку с русским («Studio Enabled», «Другой API», «Пост-клинер»,
  «Факт-чекер + пост-клинер: аудит и перезапись ответа»).
- **Терминология течёт между экранами.** Controller / Tracker / Agent — одно и то же;
  Final Agent / Main Responder / Final Generator — одно и то же; Ledger в доке это
  память, в редакторе блоков — секция; Narrative Controller = Scene Director
  (двойное имя признано в `docs/STUDIO_OVERVIEW.md`).
- **Несогласованность с ExtBlocks.** Две фичи-близнеца редактируют пресет
  по-разному: Studio — шитом поверх шита, ExtBlocks — полноэкранным роутом
  `/extensions/preset-editor/:presetId`.
- **Модели не грузятся сами** — только по тапу на дропдаун, до этого helperText
  «Open this field to load models…». Три слота × разные API-конфиги — легко решить,
  что список пустой.
- **Диагностика оторвана от настроек.** Agentic Ops есть только в Quick Access чата;
  из Studio-шита туда не попасть, хотя это основной инструмент отладки того, что
  настраиваешь рядом.
- **Редактор блоков:** сохранение мгновенное на каждый тап, undo нет; заблокированный
  блок молча игнорирует выключение (`if (_preset == null || (block.locked && !enabled)) return;`).
- **«Глобальный профиль» из Tools недетерминирован.** Без сессии берётся
  `getProfiles().first`, а это сортировка по `updatedAt desc` — «последний тронутый
  профиль».
- **Цена хода не показана нигде.** Режим гейтит только pregen-фазу
  (`applyExecutionMode` проверяет `isPreGen`), поэтому даже Direct — это не один
  запрос: автор + post-gen трекеры + аудитор/клинер + Ledger, то есть реально 3-5.
  Assisted добавляет 2-3 контроллера, Legacy — до 8. Часть контроллеров отсеивается
  по keyword-активации, так что это верхняя граница — но пользователь не видит даже
  порядка величины.

## 5. План

Порядок важен: пока режим остаётся четвёртой сущностью, любая переделка UI будет
протекать. Поэтому сначала модель, потом экран.

### Шаг 1. Режим → вычисляемое свойство (структурно)

Перестать хранить `executionMode` как источник истины. Поле в БД оставить для
совместимости, но:

- **режим вычисляется** из набора включённых pregen-контроллеров: 0 → Direct,
  только continuity + narrative (+ beauty) → Assisted, иначе → Legacy;
- убрать `applyExecutionMode` как принудительный гейт — гасить нечего, если режим
  и есть отражение `agentEnabled`;
- селектор режима превращается в **три пресета-шаблона** («применить набор»),
  без поиска пресета по имени `Loom Adapt v1`.

Побочный эффект: пропадает серый тумблер без объяснения — агент выключен, значит
выключен пользователем.

Затрагивает `studio_activation_gate.dart`, `studio_turn_config_resolver.dart`,
требует миграции существующих пресетов. Тесты на гейт уже есть.

### Шаг 2. Один словарь (дёшево, эффект большой)

Выбрать по одному имени на сущность, вынести в `en/ru.json`, применить везде.
Половина «непонятности» — отсюда.

### Шаг 3. Экран по фазам пайплайна, а не по типам объектов

Сейчас настройки сгруппированы по тому, *куда они пишутся* (config / pipeline /
preset). Надо — по тому, *что происходит на ходу*. Схема Pregen → FINAL → Cleaner
из `docs/STUDIO_OVERVIEW.md` уже даёт структуру:

```
Studio                                    [вкл]
Сборка: Assisted · 4 запроса на ответ
─────────────────────────────────────────────
1. ПОДГОТОВКА                        Глобально
   Continuity Controller             [вкл]  ⚙
   Scene Director                    [вкл]  ⚙
   Beauty                            [выкл] ⚙
   + ещё 5 контроллеров (Legacy)
   Модель для всех: gpt-5-mini · Другой API

2. НАПИСАНИЕ                         Глобально
   Автор (Main Responder)                   ⚙
   Модель: claude-opus-5 · сэмплеры

3. ПРОВЕРКА                          Глобально
   Auditor + POST-cleaner            [вкл]  ⚙
   Модель: gpt-5-mini
   Контекст трекерам: 1 · 2 · 3 · 5
─────────────────────────────────────────────
Что было в прошлом ходу →      (Agentic Ops)
Продвинутое: промпт-блоки, Recovery →
```

Что меняется:

- **шит Agents исчезает** — тумблеры переезжают в «Подготовку», минус уровень
  вложенности;
- **Post-Gen перестаёт быть отдельной строкой** — это и есть «Проверка»;
- **слоты моделей приклеены к фазам**, а не висят отдельным списком «Models»;
- **⚙ у агента** ведёт в его промпт-блок: блок открывается *от агента*, а не через
  «выбери секцию → найди блок». Общий редактор блоков остаётся, но уезжает
  в «Продвинутое»;
- **подписи scope** («Глобально» / «Этот чат») у каждой группы.

### Шаг 4. Показать цену хода

Строка «N запросов на ответ» в шапке — самая дешёвая честная обратная связь. Делает
выбор режима самоочевидным: видно, что Legacy это ~10 запросов вместо 4 у Direct.
Заодно снимает частое заблуждение, что «Direct = как будто Studio выключена».

### Шаг 5. Пресеты — переименовать и объяснить

`Studio Preset` → **«Сборка»** (или «Конфигурация пайплайна») с подзаголовком
«контроллеры, промпты и режим». В селектор добавить «Редактировать» рядом
с Export / Delete.

## 6. Порядок работ

По соотношению «эффект / риск»:

1. **Шаг 2** (словарь + локализация) — не трогает логику, день работы.
2. **Шаг 3** (перекомпоновка экрана + подписи scope) — чистый UI поверх существующих
   данных.
3. **Шаг 1** (режим как вычисляемое) — самое ценное, но трогает гейт и требует
   миграции пресетов.
4. Шаги 4-5 — по остаточному принципу.

Шаги 2 и 3 можно свести в один PR: вдвоём они уже снимают ощущение перегруженности,
не меняя поведения пайплайна.
